---
title: "get_deck_status"
description: "Get the current status and progress of a deck generation job."
---

<Info>
**Type:** Read · **Required scope:** `decks:read` · **Cost:** Free
</Info>

## Parameters

<ParamField path="job_id" type="string" required>
  The job ID returned by [`create_deck`](/tools/create-deck) or [`fill_templates`](/tools/fill-templates).
</ParamField>

## Response

Returns the job object, the same shape as [`create_deck`](/tools/create-deck#response).

<ResponseField name="status" type="string">
  One of `queued`, `running`, `succeeded`, `failed`, `canceled`.
</ResponseField>
<ResponseField name="kind" type="string">
  `generate` ([`create_deck`](/tools/create-deck)) or `fill_templates` ([`fill_templates`](/tools/fill-templates)).
</ResponseField>
<ResponseField name="progress" type="object">
  Empty (`{}`) until the job starts. See [Progress fields](#progress-fields).
</ResponseField>
<ResponseField name="credits_charged" type="integer | null">
  Final credits charged once settled; refunded to `0` on failure or cancel.
</ResponseField>
<ResponseField name="error" type="object | null">
  Why the job (or an attempt of it) failed: `message`, the `stage` it failed in, and the `attempt`.
</ResponseField>
<ResponseField name="enterprise" type="boolean">
  `true` when the job runs with [enterprise data handling](/authentication#enterprise-data-handling).
</ResponseField>
<ResponseField name="library" type="object">
  `fill_templates` jobs only: the library `deck_id` and `exclude_member_ids`, or the `template_ids`, that the job fills.
</ResponseField>

## Progress fields [#progress-fields]

| Field | When | Meaning |
| --- | --- | --- |
| `stage` | Once running | `loading_template`, `generating_slides` (`create_deck`) or `filling_templates` (`fill_templates`), `finalizing`, `rendering_previews`, `done` |
| `slides_done` | Once running | Slides finished so far. When the job succeeds, the number of slides in the deck. |
| `target_slides` | Once running | Slides requested (for `fill_templates`, the most the deck may have) |
| `library_slides` | When any slide comes from the library | How many of `slides_done` were built from library templates. They cost 1 credit each. |
| `detail` | `fill_templates` | The current step, such as `planning the storyline` or `filling the slides` |
| `report` | `fill_templates`, once the slides are filled | What was filled, skipped, and left to confirm. See [below](#fill-templates-report). |
| `preview_slides` | `succeeded` | How many slides have a rendered preview image. The [deck card](/interactive-cards#deck-card) shows them. |
| `attributions` | `succeeded`, when present | Credit lines for third-party assets in the deck, such as `"Logos by Logo.dev"`. Pass them on to the user with the deck. |

### fill_templates report [#fill-templates-report]

For `fill_templates` jobs, `progress.report` says what Decky did with the material. Pass the placeholders and gaps on to the user: they are the facts to confirm or supply.

| Field | Meaning |
| --- | --- |
| `deck` | The library deck's title (deck fills only) |
| `slides` | Each slide built: `slide` number, its new `title`, and the library `template` (title) and `template_id` it came from |
| `skipped` | Slides that could not be filled, with a `reason`. For example, `no usable chart data (…)` for a chart slide without real data in the material |
| `placeholders` | Visible `[… — to confirm]` (or `[TBC]`) placeholders in the deck, as `slide N <slot>: <value>` |
| `gaps` | Facts the deck needs that the material did not give |
| `dropped` | Deck slides left out of the storyline, with a `reason` (deck fills only) |
| `kept_sample_pictures` | Picture slots that kept the template's sample picture. Swap them for your own in PowerPoint. |

## Status lifecycle

```mermaid
flowchart LR
    Q[queued] --> R[running]
    R --> S[succeeded]
    R --> F[failed]
    R --> C[canceled]
```

| Status | `progress.slides_done` | `finished_at` | `credits_charged` |
| --- | --- | --- | --- |
| `queued` | Not set (`progress` is `{}`) | `null` | `null` |
| `running` | Updates as slides finish | `null` | `null` |
| `succeeded` | Equal to slides produced | Set | Final value |
| `failed` | Last value before failure | Set | Refunded to 0 |
| `canceled` | Last value | Set | Refunded to 0 |

<Note>
If an attempt fails, Decky retries the job once. Its status goes back to `queued`, and `error` holds the failed attempt's message.
</Note>

## Polling recommendations

<Tip>
Your assistant polls automatically. In clients that show the [deck card](/interactive-cards#deck-card), the card follows the job itself and tells the assistant when the deck is done, so no polling is needed there. You only need to call this tool manually if you're building a custom integration.
</Tip>

- Poll every **10 seconds** while status is `queued` or `running`.
- A 10-slide deck typically takes **3–7 minutes**; a 40-slide deck up to **20 minutes**.
- Stop polling as soon as status is `succeeded`, `failed`, or `canceled`.

## Errors

| Error | Cause |
| --- | --- |
| `Deck job 'X' not found` | Invalid job ID, or it belongs to another account. Call [`list_decks`](/tools/list-decks). |
